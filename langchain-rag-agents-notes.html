Vector stores

Where this fits: RAG has four building blocks. Video 10 covered document loaders and Video 11 text splitters. This video is the third block, and Video 13 is the fourth.

Why we need them: the movie recommender story

You run an IMDb-style site with a database of movies (name, director, actors, genre, release date, hit or flop). You want "similar movies" at the bottom of each page.

Attempt 1: keyword matching

  • Two movies are similar if director, actor, genre and release year match.
  • Flaw 1, false matches: My Name Is Khan recommends Kabhi Alvida Naa Kehna. Same director and lead actor, completely different story.
  • Flaw 2, missed matches: Taare Zameen Par and A Beautiful Mind share no keywords, yet both are about a brilliant person fighting a condition.

Attempt 2: compare the plots

  • Similar stories mean similar movies, so compare plots instead of keywords.
  • Turn each plot into an embedding, a vector that captures meaning.
  • Similar plots end up close together. Measure that with cosine similarity.
  • This is semantic search: it matches meaning, not words.
Interview · the three problems a vector store solves
  1. Generate embeddings for millions of items.
  2. Store them. A relational database (MySQL, Oracle) is not built to store vectors or compare them.
  3. Search them fast. Comparing a query with a million vectors one by one is too slow.

What a vector store is

Interview · definition

A vector store is a system designed to store and retrieve data represented as numerical vectors, along with each vector's metadata and original text.

Core featureWhat it means
StorageKeeps vectors plus metadata, either in memory (fast lookups) or on disk (durable, large scale)
Similarity searchReturns the vectors closest to a query vector
IndexingA data structure that makes search fast on huge collections (see below)
CRUDAdd, read, update and delete vectors

Use cases: semantic search, RAG, recommender systems, image and multimedia search.

Indexing: how search stays fast

The video's example uses clustering. Group 1 million vectors into 10 clusters of about 100,000 each, and store each cluster's centre (centroid). For a query, compare it with the 10 centroids first, then search only inside the closest cluster.

Beyond the video · index names to know
  • Flat: brute-force, exact, slow at scale.
  • IVF (inverted file): the clustering idea above.
  • HNSW: a layered graph you walk towards the query. The default in most vector databases.
  • All of these are ANN (approximate nearest neighbour) search: they trade a little accuracy for a lot of speed.

Vector store vs vector database

Vector storeVector database
WhatLightweight library or service to store vectors and run similarity searchA vector store plus database features
Extra featuresUsually noneDistributed architecture for scaling, backup and restore, ACID transactions, concurrency control, authentication
Best forPrototypes, small apps, single machineProduction, big data, many users
ExamplesFAISSMilvus, Qdrant, Weaviate, Pinecone
Interview · one-liner

"A vector database is effectively a vector store with extra database features." So every vector database is a vector store, but not every vector store is a vector database. Chroma sits in the middle: lightweight like a store, with some database features.

Vector stores in LangChain

LangChain wraps FAISS, Chroma, Pinecone, Qdrant, Weaviate and many more behind one common interface, so switching stores means changing one or two lines.

Chroma's data hierarchy

chroma_crud.pyNeeds OPENAI_API_KEY · not run
# pip install langchain-openai langchain-chroma
from langchain_openai import OpenAIEmbeddings
from langchain_chroma import Chroma
from langchain_core.documents import Document

docs = [
    Document(page_content="Virat Kohli is one of the most successful and consistent batsmen in IPL history.",
             metadata={"team": "Royal Challengers Bangalore"}),
    Document(page_content="Rohit Sharma is the most successful captain in IPL history, with five titles.",
             metadata={"team": "Mumbai Indians"}),
    Document(page_content="MS Dhoni, known as Captain Cool, has led Chennai Super Kings to multiple titles.",
             metadata={"team": "Chennai Super Kings"}),
    Document(page_content="Jasprit Bumrah is one of the best fast bowlers in T20 cricket.",
             metadata={"team": "Mumbai Indians"}),
    Document(page_content="Ravindra Jadeja is a dynamic all-rounder who bowls left-arm spin.",
             metadata={"team": "Chennai Super Kings"}),
]

vector_store = Chroma(
    embedding_function=OpenAIEmbeddings(),
    persist_directory="my_chroma_db",     # saved to disk automatically, no .persist() needed
    collection_name="sample",
)

# Create
ids = vector_store.add_documents(docs)          # returns one id per document

# Read
vector_store.get(include=["embeddings", "documents", "metadatas"])

# Search
vector_store.similarity_search(query="Who among these are a bowler?", k=2)
vector_store.similarity_search_with_score(query="Who among these are a bowler?", k=2)  # score = distance
vector_store.similarity_search_with_score(query="", filter={"team": "Chennai Super Kings"})  # metadata filter

# Update
updated = Document(page_content="Virat Kohli, former RCB captain, is known for aggressive batting.",
                   metadata={"team": "Royal Challengers Bangalore"})
vector_store.update_document(document_id=ids[0], document=updated)

# Delete
vector_store.delete(ids=[ids[0]])
Gotcha · reading the score

similarity_search_with_score in Chroma and FAISS returns a distance (L2 by default), so lower is closer. If you want a 0 to 1 score where higher is better, use similarity_search_with_relevance_scores.

The same calls on FAISS, which runs locally with no server:

faiss_store.pyRan
# pip install faiss-cpu langchain-community
from langchain_community.vectorstores import FAISS

vector_store = FAISS.from_documents(docs, OpenAIEmbeddings())   # embed + index in one call

vector_store.similarity_search("Who among these are a bowler?", k=2)
vector_store.similarity_search("batsman", k=5, filter={"team": "Chennai Super Kings"})

ids = list(vector_store.index_to_docstore_id.values())
vector_store.delete(ids=[ids[0]])

vector_store.save_local("faiss_index")                          # FAISS is in-memory: save it yourself
vector_store = FAISS.load_local("faiss_index", OpenAIEmbeddings(),
                                allow_dangerous_deserialization=True)  # loads a pickle, so trust the file
Gotcha

FAISS.load_local refuses to load without allow_dangerous_deserialization=True, because the docstore is a pickle and a malicious pickle can run code. Only load index files you created yourself.

Retrievers

Interview · definition

A retriever is a component that fetches relevant documents from a data source in response to a user's query. Input: a query string. Output: a list of Document objects. Every retriever is a runnable, so you call it with .invoke() and can put it inside a chain.

Two ways to classify retrievers

Wikipedia retriever

Sends your query to the Wikipedia API and returns the most relevant articles as documents.

wikipedia_retriever.pyNeeds internet · not run
# pip install wikipedia langchain-community
from langchain_community.retrievers import WikipediaRetriever

retriever = WikipediaRetriever(top_k_results=2, lang="en")
docs = retriever.invoke("the geopolitical history of india and pakistan from the perspective of a chinese")

for i, doc in enumerate(docs):
    print(f"--- Result {i + 1} ---\n{doc.page_content[:500]}")
Interview · retriever vs document loader

A loader loads exactly the source you point it at. A retriever decides which content is relevant to the query. The Wikipedia retriever is a retriever because it searches and picks articles for your question.

Vector store retriever

The most common retriever. It embeds the query and runs similarity search on a vector store.

vectorstore_retriever.pyRan
from langchain_community.vectorstores import FAISS     # or: from langchain_chroma import Chroma
from langchain_openai import OpenAIEmbeddings

vector_store = FAISS.from_documents(docs, OpenAIEmbeddings())
retriever = vector_store.as_retriever(search_kwargs={"k": 2})

results = retriever.invoke("What is Chroma used for?")   # list of Document
Interview · why not just call similarity_search?

vector_store.similarity_search() gives the same documents here. A retriever adds two things: it is a runnable (it plugs into LCEL chains), and it lets you switch search strategies (search_type="mmr", score thresholds, multi-query on top) without changing the rest of the code.

Maximum Marginal Relevance (MMR)

Problem: plain similarity search often returns near-duplicates. Five chunks that say the same thing waste the LLM's context.

Interview · definition

MMR is an information-retrieval algorithm designed to reduce redundancy in the results while keeping high relevance to the query. Each next document is chosen for being relevant to the query and different from the documents already picked.

lambda_multBehaviour
1Pure similarity search (no diversity)
0.5 (default)Balanced
0Maximum diversity
mmr_retriever.pyRan
vector_store = FAISS.from_documents(docs, OpenAIEmbeddings())

retriever = vector_store.as_retriever(
    search_type="mmr",                               # default is "similarity"
    search_kwargs={"k": 3, "lambda_mult": 0.5},      # also: "fetch_k": 20
)
results = retriever.invoke("What is langchain?")

Multi-query retriever

Problem: vague queries retrieve poorly. "How can I stay healthy?" might mean "what should I eat?", "how often should I exercise?" or "how do I manage stress?", and each has different relevant documents.

multi_query_retriever.pyRan
# pip install langchain-classic
from langchain_classic.retrievers import MultiQueryRetriever
from langchain_openai import ChatOpenAI

multiquery_retriever = MultiQueryRetriever.from_llm(
    retriever=vector_store.as_retriever(search_kwargs={"k": 5}),
    llm=ChatOpenAI(model="gpt-3.5-turbo"),
)
results = multiquery_retriever.invoke("How to improve energy levels and maintain balance?")
Gotcha · cost

Every multi-query call is 1 extra LLM call plus 3 searches. It improves recall, but it is slower and costs more.

Contextual compression retriever

Problem: a retrieved chunk can mix relevant and irrelevant text. The video's example document: "The Grand Canyon is a famous natural site. Photosynthesis is how plants convert light into energy. Many tourists visit every year." For the query "What is photosynthesis?" only the middle sentence matters.

contextual_compression.pyRan
from langchain_classic.retrievers import ContextualCompressionRetriever
from langchain_classic.retrievers.document_compressors import LLMChainExtractor

base_retriever = vector_store.as_retriever(search_kwargs={"k": 5})
compressor = LLMChainExtractor.from_llm(ChatOpenAI(model="gpt-3.5-turbo"))

compression_retriever = ContextualCompressionRetriever(
    base_retriever=base_retriever,
    base_compressor=compressor,
)
results = compression_retriever.invoke("What is photosynthesis?")
Gotcha

LLMChainExtractor makes one LLM call per retrieved document. When nothing in a document is relevant, the LLM answers NO_OUTPUT and that document is removed, so you can get back fewer than k documents.

retriever.get_relevant_documents(q) appears in older tutorials. It is deprecated. Use retriever.invoke(q).

RAG explained: why it exists and how it works

Where an LLM's knowledge lives

An LLM is a transformer pretrained on a huge dataset. Everything it learned is stored as numbers in its weights and biases, so this is called parametric knowledge. More parameters means more knowledge (7B < 13B < 70B). You access it by prompting.

Three situations where prompting fails

1 · Private data

"What was explained at this point of the course video?" The model never saw your course videos during pretraining.

2 · Recent data

"What is today's biggest news in India?" Every LLM has a knowledge cutoff date.

3 · Hallucination

Confidently wrong facts, such as "Einstein played football for Germany in his early years".

Solution 1: fine-tuning

Analogy: an engineering graduate (pretrained model) joins a company and gets job-specific training (fine-tuning) before doing real work.

Fine-tuning typeData
Supervised fine-tuning (SFT)Labelled prompt and desired-output pairs. The most common.
Continued pretrainingUnlabelled domain text, such as medical books
RLHFHuman preference rankings, teaches real-world behaviour
LoRA / QLoRAParameter-efficient: freeze the base model, train small adapter weights

How it addresses the three problems: train on private data, re-train for recent data, and add tricky prompts labelled "I don't know" to reduce hallucination.

Interview · problems with fine-tuning
  1. Computationally expensive: you are training a very large model.
  2. Needs strong technical expertise: AI engineers and data scientists.
  3. Frequent updates are painful: every time the course catalogue changes you fine-tune again. Removing outdated information is also hard.

Solution 2: in-context learning

Interview · definition

In-context learning is an LLM's ability to solve a task purely from examples given in the prompt, without updating its weights. Giving a few examples is called few-shot prompting.

few_shot_prompt.txt
Below are examples of text labelled with their sentiment.

Text: I love this phone. It's so smooth.        Sentiment: Positive
Text: This app crashes a lot.                   Sentiment: Negative
Text: The camera is amazing!                    Sentiment: Positive

Text: I hate the battery life.                  Sentiment:
Interview · emergent property

An emergent property is a behaviour that suddenly appears when a system reaches a certain scale, even though nobody programmed it. In-context learning is one. Smaller models like GPT-1 and GPT-2 could not do it well; GPT-3 (175B parameters) could. It was first described in the GPT-3 paper "Language Models are Few-Shot Learners" (2020).

RAG = in-context learning, but send the context instead of examples

The video's example: a student watching a 2-hour linear regression lecture gets stuck on gradient descent. Instead of sending only the question, send the question plus the transcript from minute 5 to minute 25, where gradient descent is taught. The LLM can now answer from that context.

Interview · definition

RAG (Retrieval-Augmented Generation) is a way to make a language model smarter by giving it extra information at the time you ask your question. It is the marriage of two older ideas: information retrieval and text generation.

rag_prompt.txt
You are a helpful assistant.
Answer the question ONLY from the provided context.
If the context is insufficient, just say you don't know.

{context}
Question: {question}

The four steps of RAG

Interview · why chunk at all?
  • LLM context windows are limited, so you cannot send the whole knowledge base.
  • Semantic search works better on small focused chunks. One embedding for a whole book blurs all its topics together.

How RAG solves the three problems

ProblemHow RAG solves it
Private dataYour private documents are in the vector store, and the relevant parts are sent as context
Recent dataAdd new documents to the index. No retraining.
HallucinationThe prompt grounds the model: "answer ONLY from the context, else say you don't know"
Fine-tuningIn-context learningRAG
Changes model weights?YesNoNo
CostHigh (GPU training)LowLow to medium (embeddings + vector store)
Updating knowledgeRetrainChange the promptRe-index the new documents
Expertise neededHighLowMedium
Best forStyle, format, behaviour, domain languageShowing the task formatFacts from large, private or changing data
Beyond the video · the usual interview follow-up

"RAG or fine-tuning?" A good answer: use RAG for knowledge (facts that change or are private) and fine-tuning for behaviour (tone, output format, a specialised skill). They combine well: a fine-tuned model inside a RAG pipeline. RAG also lets you cite sources, which fine-tuning cannot.

Project: a YouTube chatbot with RAG

The goal: paste a long YouTube video (the video uses a 2-hour podcast with Demis Hassabis of Google DeepMind) and ask questions like "Is nuclear fusion discussed in this video?" instead of watching all of it. The idea is a Chrome extension; this video builds the backend.

Step 1 · Indexing

indexing.pyNeeds OPENAI_API_KEY + internet · split/index ran
# pip install youtube-transcript-api langchain-community langchain-openai faiss-cpu tiktoken python-dotenv
from youtube_transcript_api import YouTubeTranscriptApi, TranscriptsDisabled
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_openai import OpenAIEmbeddings
from langchain_community.vectorstores import FAISS

# 1a. Ingestion: fetch the transcript
video_id = "Gfr50f6ZBvo"                  # only the id, not the full URL
try:
    fetched = YouTubeTranscriptApi().fetch(video_id, languages=["en"])
    transcript = " ".join(snippet.text for snippet in fetched)   # flatten to plain text
except TranscriptsDisabled:
    print("No captions available for this video.")

# 1b. Text splitting
splitter = RecursiveCharacterTextSplitter(chunk_size=1000, chunk_overlap=200)
chunks = splitter.create_documents([transcript])   # list[str] in, list[Document] out

# 1c + 1d. Embedding generation and storage in a vector store
embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
vector_store = FAISS.from_documents(chunks, embeddings)
Gotcha · library changed

The video uses YouTubeTranscriptApi.get_transcript(video_id), which returned a list of dicts. From youtube-transcript-api 1.0 that static method is gone: create an instance, call .fetch(), and read snippet.text. YouTube also blocks transcript requests from many cloud IPs (Colab included), which raises IpBlocked / RequestBlocked. Run it locally or use a proxy.

Steps 2 to 4 · Retrieval, augmentation, generation

retrieve_augment_generate.pyRan
from langchain_core.prompts import PromptTemplate
from langchain_openai import ChatOpenAI

# 2. Retrieval
retriever = vector_store.as_retriever(search_type="similarity", search_kwargs={"k": 4})

# 3. Augmentation
llm = ChatOpenAI(model="gpt-4o-mini", temperature=0.2)
prompt = PromptTemplate(
    template="""You are a helpful assistant.
Answer ONLY from the provided transcript context.
If the context is insufficient, just say you don't know.

{context}
Question: {question}""",
    input_variables=["context", "question"],
)

question = "is the topic of nuclear fusion discussed in this video? if yes then what was discussed"
retrieved_docs = retriever.invoke(question)
context_text = "\n\n".join(doc.page_content for doc in retrieved_docs)
final_prompt = prompt.invoke({"context": context_text, "question": question})

# 4. Generation
answer = llm.invoke(final_prompt)
print(answer.content)

Same thing as one LCEL chain

rag_chain.pyRan
from langchain_core.runnables import RunnableParallel, RunnablePassthrough, RunnableLambda
from langchain_core.output_parsers import StrOutputParser

def format_docs(retrieved_docs):
    return "\n\n".join(doc.page_content for doc in retrieved_docs)

parallel_chain = RunnableParallel({
    "context": retriever | RunnableLambda(format_docs),
    "question": RunnablePassthrough(),
})
# parallel_chain.invoke("who is Demis") -> {"context": "...chunks...", "question": "who is Demis"}

main_chain = parallel_chain | prompt | llm | StrOutputParser()
main_chain.invoke("Can you summarize the video")
Interview · why RunnablePassthrough?

The prompt needs two variables but the chain receives one string. RunnableParallel fans the string out: the retriever branch turns it into context, and RunnablePassthrough forwards the original question unchanged.

How to make it production-grade (improvement ideas from the video)

Interview · RAGAS metrics
  • Faithfulness: is every claim in the answer supported by the retrieved context? (catches hallucination)
  • Answer relevancy: does the answer actually address the question?
  • Context precision: are the retrieved chunks relevant, and ranked first?
  • Context recall: did retrieval fetch everything needed to answer?
Beyond the video · reranking in one line

Retrieve more candidates (say 20) with fast vector search, then score each (query, chunk) pair with a slower but more accurate cross-encoder model and keep the best 4. Vector search is fast and approximate; the reranker is slow and precise.

Tools

The playlist now moves to its third part, agents. Tools are the first building block.

Why tools: an LLM has a brain but no hands

An LLM can think (reason, understand, generate language) but cannot do anything: it cannot search the internet, call an API, run code or book a ticket. Think of a body with a brain and a voice but no hands or legs. Tools give it hands and legs.

Interview · definition

"A tool is just a Python function that is packaged in a way the LLM can understand and call when needed." The LLM decides when to use which tool and with what inputs; the tool does the work and reports back.

Built-in vs custom tools

Built-in (ready-made by LangChain)

  • DuckDuckGoSearchRun: web search
  • WikipediaQueryRun: Wikipedia summaries
  • PythonREPLTool: run Python code
  • ShellTool: run shell commands
  • RequestsGetTool: HTTP GET
  • Gmail, Slack, SQL database tools and more

Custom (you write them) when

  • You call your own APIs
  • You encode business logic
  • The LLM must touch your database or product
builtin_tools.pyNeeds internet · not run
# pip install langchain-community ddgs
from langchain_community.tools import DuckDuckGoSearchRun

search_tool = DuckDuckGoSearchRun()
results = search_tool.invoke("top news in india today")   # tools are runnables: .invoke()

print(search_tool.name)          # duckduckgo_search
print(search_tool.description)   # what the LLM reads to decide when to use it
print(search_tool.args)          # {'query': {...}}
Gotcha · ShellTool

ShellTool().invoke("ls") runs a real command on your machine. Letting an LLM choose shell commands is dangerous (it could delete files). Only use it inside a sandbox or container.

Three ways to create a custom tool

tool_decorator.pyRan
from langchain_core.tools import tool

# Step 1: a plain function. Step 2: add type hints. Step 3: add @tool.
@tool
def multiply(a: int, b: int) -> int:
    """Multiply two numbers"""          # the docstring becomes the tool description
    return a * b

multiply.invoke({"a": 3, "b": 5})        # 15
multiply.name                            # 'multiply'
multiply.description                     # 'Multiply two numbers'
multiply.args                            # {'a': {'title': 'A', 'type': 'integer'}, 'b': {...}}
multiply.args_schema.model_json_schema() # the JSON schema the LLM actually sees
Interview · what does the LLM see?

Not your Python code. When a tool is connected, the LLM receives only its schema: name, description and a JSON schema of the arguments. So type hints and a clear docstring are not optional; they are how the LLM knows when and how to call the tool.

structured_tool.pyRan
from langchain_core.tools import StructuredTool
from pydantic import BaseModel, Field

class MultiplyInput(BaseModel):
    a: int = Field(required=True, description="The first number to add")
    b: int = Field(required=True, description="The second number to add")

def multiply_func(a: int, b: int) -> int:
    return a * b

multiply_tool = StructuredTool.from_function(
    func=multiply_func,
    name="multiply",
    description="Multiply two numbers",
    args_schema=MultiplyInput,
)
multiply_tool.invoke({"a": 3, "b": 3})   # 9
base_tool.pyRan
from typing import Type
from langchain_core.tools import BaseTool

class MultiplyTool(BaseTool):
    name: str = "multiply"
    description: str = "Multiply two numbers"
    args_schema: Type[BaseModel] = MultiplyInput

    def _run(self, a: int, b: int) -> int:    # add _arun for an async version
        return a * b

MultiplyTool().invoke({"a": 3, "b": 3})   # 9
Gotcha · imports

The video imports StructuredTool and BaseTool from langchain.tools. On LangChain 1.x import them from langchain_core.tools, which works on every version.

Toolkits

A toolkit is a collection of related tools bundled together for reuse, such as a Google Drive toolkit with upload, search and read tools.

Interview · tools and agents

An agent = LLM (reasoning and decisions) + tools (actions). Tools on their own just sit there; the LLM decides when to use them.

Tool calling

Four pieces: tool creation (Video 16), tool binding, tool calling and tool execution.

Interview · definitions
  • Tool binding: registering tools with an LLM so it knows what tools exist, what each does, and what input format to use.
  • Tool calling: the LLM decides, during the conversation, that a tool should be used and returns a structured call (tool name + arguments). The LLM does not run the tool.
  • Tool execution: actually running the Python function with those arguments, then returning the result as a ToolMessage.
Gotcha

Not every model supports tool calling. Check the provider docs (in Ollama, look for the "tools" tag). The LLM also does not always call a tool: "Hi, how are you?" gets a normal reply with empty tool_calls.

tool_calling.pyRan
from langchain_openai import ChatOpenAI
from langchain_core.tools import tool
from langchain_core.messages import HumanMessage

@tool
def multiply(a: int, b: int) -> int:
    """Given 2 numbers a and b this tool returns their product"""
    return a * b

llm = ChatOpenAI()
llm_with_tools = llm.bind_tools([multiply])          # binding

messages = [HumanMessage("can you multiply 3 with 1000")]
result = llm_with_tools.invoke(messages)             # calling
messages.append(result)
result.tool_calls[0]
# {'name': 'multiply', 'args': {'a': 3, 'b': 1000}, 'id': 'call_...', 'type': 'tool_call'}

tool_result = multiply.invoke(result.tool_calls[0])  # execution: pass the WHOLE tool_call
# ToolMessage(content='3000', name='multiply', tool_call_id='call_...')
messages.append(tool_result)

llm_with_tools.invoke(messages).content              # 'The product of 3 and 1000 is 3000.'
Interview · why pass the whole tool_call?

Invoking a tool with the full tool-call dict (not just args) returns a ToolMessage carrying the same tool_call_id. The LLM uses that id to match each result to the call it made, which matters when it requests several tools at once.

Project: real-time currency converter, and InjectedToolArg

Two tools: get_conversion_factor calls an exchange-rate API, and convert multiplies an amount by that rate. The problem: the LLM must fill in conversion_rate for convert in the same turn, before the first tool has run, so it guesses a number (a hallucinated rate).

The fix is to mark that argument as injected. The LLM is not shown it and does not fill it; your code sets it at runtime from the first tool's output.

currency_converter.pyRan
import json, requests
from typing import Annotated
from langchain_core.tools import tool, InjectedToolArg

@tool
def get_conversion_factor(base_currency: str, target_currency: str) -> float:
    """This function fetches the currency conversion factor between a given base currency and a target currency"""
    url = f"https://v6.exchangerate-api.com/v6/YOUR_API_KEY/pair/{base_currency}/{target_currency}"
    return requests.get(url).json()

@tool
def convert(base_currency_value: int, conversion_rate: Annotated[float, InjectedToolArg]) -> float:
    """given a currency conversion rate this function calculates the target currency value from a given base currency value"""
    return base_currency_value * conversion_rate

llm_with_tools = ChatOpenAI().bind_tools([get_conversion_factor, convert])

messages = [HumanMessage("What is the conversion factor between INR and USD, "
                         "and based on that can you convert 10 inr to usd")]
ai_message = llm_with_tools.invoke(messages)
messages.append(ai_message)

for tool_call in ai_message.tool_calls:
    if tool_call["name"] == "get_conversion_factor":
        tool_message1 = get_conversion_factor.invoke(tool_call)
        conversion_rate = json.loads(tool_message1.content)["conversion_rate"]
        messages.append(tool_message1)
    if tool_call["name"] == "convert":
        tool_call["args"]["conversion_rate"] = conversion_rate     # inject the real value
        tool_message2 = convert.invoke(tool_call)
        messages.append(tool_message2)

llm_with_tools.invoke(messages).content
Gotcha · what .args shows now

In the video, convert.args still lists conversion_rate. On langchain-core 1.5 .args hides injected arguments; you see them only in convert.args_schema. What the LLM receives is convert.tool_call_schema, which never includes them.

Interview · is this an agent?

No. The LLM suggested the tools, but we hard-coded the flow: which tool runs first, how its output feeds the next, when to stop. An agent decides all of that itself in a loop. That is Video 18.

Building an AI agent (ReAct)

The problem: a Delhi to Goa trip

Planning a trip means picking dates, comparing flights and trains, booking hotels, planning local travel and sightseeing, paying, and maybe calling hotels. It takes days across many websites. An AI agent takes the high-level goal ("plan a Goa trip from 1 to 7 May") and does the research, comparisons and bookings itself, asking you only for decisions.

Interview · definition

"An AI agent is an intelligent system that receives a high-level goal from a user and autonomously plans, decides and executes a sequence of actions by using external tools, APIs and knowledge sources, all while maintaining context, reasoning over multiple steps, adapting to new information and optimising for the intended outcome."

CharacteristicMeaning
Goal-drivenYou say what, not how
PlanningBreaks the problem into steps and executes them one by one
Tool-awareKnows which tools it has and when to use each
Context / memoryRemembers progress, user details and preferences
AdaptiveRe-plans when something fails (train API down, so suggest a bus)

ReAct = Reasoning + Acting

ReAct is a design pattern for agents (one of several, and the most famous). The LLM alternates between thinking and acting in a loop, and each thought is written out, so you can see why the agent did what it did. It comes from the paper "ReAct: Synergizing Reasoning and Acting in Language Models" (2022).

Walk-through from the video: "What is the population of the capital of France?"

react_trace.txt
Thought: To answer this, I first need the capital of France.
Action: search
Action Input: capital of France
Observation: Paris is the capital of France.
Thought: Now I need the population of Paris.
Action: search
Action Input: population of Paris
Observation: About 2.1 million people live in Paris.
Thought: I now know the final answer
Final Answer: Paris, the capital of France, has about 2.1 million people.

import requests
from langchain_openai import ChatOpenAI
from langchain_core.tools import tool
from langchain_community.tools import DuckDuckGoSearchRun
from langchain_classic.agents import create_react_agent, AgentExecutor
from langchain_classic import hub

search_tool = DuckDuckGoSearchRun()

@tool
def get_weather_data(city: str) -> str:
    """This function fetches the current weather data for a given city"""
    url = f"https://api.weatherstack.com/current?access_key=YOUR_WEATHERSTACK_KEY&query={city}"
    return requests.get(url).json()

llm = ChatOpenAI()

# Step 1: pull the standard ReAct prompt from LangChain Hub
prompt = hub.pull("hwchase17/react")

# Step 2: create the agent (the brain: decides the next step)
agent = create_react_agent(llm=llm, tools=[search_tool, get_weather_data], prompt=prompt)

# Step 3: wrap it in an executor (runs the loop and the tools)
agent_executor = AgentExecutor(agent=agent, tools=[search_tool, get_weather_data], verbose=True)

# Step 4: invoke
response = agent_executor.invoke(
    {"input": "Find the capital of Madhya Pradesh, then find it's current weather condition"}
)
response["output"]

Interview · the prompt variables
  • {tools}: name and description of every tool
  • {tool_names}: the allowed tool names
  • {input}: the user's question
  • {agent_scratchpad}: everything so far (previous thoughts, actions, observations). This is how the stateless LLM "remembers" earlier steps.

Gotcha · when the loop goes wrong

If the LLM writes text that does not match the format, the output parser fails; pass handle_parsing_errors=True to AgentExecutor. Limit runaway loops with max_iterations (default 15). Add return_intermediate_steps=True to get every (AgentAction, observation) pair back.

Ollama: run open-source LLMs on your own machine

Proprietary vs open-source models

Proprietary (GPT, Claude, Gemini)

  • Weights stay with the company; you call an API
  • Pay per token
  • Your prompts and data leave your machine

Open-source (Llama, Qwen, Gemma, DeepSeek, Mistral)

  • Weights are free to download
  • "Free in theory, hard in practice": where do you store the raw weights, how do you fit them into RAM / VRAM, are they compatible with your system?
Interview · definition

Ollama is a tool that helps you download, run and manage large language models on your own computer. It handles storage, memory loading, compatibility and serving, so you only focus on using the model. The video's analogy: Ollama is WhatsApp for open-source models. In WhatsApp you just send and receive, and the app handles everything behind the scenes.

BenefitWhy
Privacy and data controlYour data never leaves your computer
Low latency, offline accessInternet needed only to download the model
Cost predictabilityNo per-token bill
Simple setupOne-click install, one command per model. No ML engineer needed.
Prebuilt model libraryLlama, Qwen, Gemma, DeepSeek... already converted; filter by capability: vision, tools, thinking, embedding, cloud
CustomisationParameters, system prompts, your own models via a Modelfile
No vendor lock-inSwitch models freely
Gotcha · hardware

The model runs in your RAM or VRAM, so hardware decides which models you can use: roughly 8 GB+ RAM and a recent CPU for small models, more for bigger ones; a GPU is optional but faster. Sizes vary a lot (qwen3-vl 2B is about 2 GB, 8B about 6 GB). A model too big for your memory can freeze or crash the machine. And a model can only do what it was built for: images need a vision model (e.g. gemma3:4b), tool calling needs a tools model (e.g. qwen3:8b).

Architecture: everything talks to one local REST server

Tool calling with Ollama

Same idea as Video 17, without LangChain: an inventory lookup plus a loyalty-discount function. The model suggests calls; your code runs them and sends results back with role: "tool".

ollama_tools.pyRan · ollama.chat mocked
import ollama

inventory_db = {
    "laptop": {"stock": 5, "base_price": 1200},
    "monitor": {"stock": 0, "base_price": 300},
    "keyboard": {"stock": 25, "base_price": 80},
}

def check_inventory(product_name: str) -> dict:
    """Get stock and price for a product"""
    return inventory_db.get(product_name.lower(), {"stock": 0, "base_price": None})

def calculate_loyalty_discount(base_price: float, years_as_customer: int) -> float:
    """Calculate final price based on loyalty years"""
    discount = min(years_as_customer * 0.05, 0.30)   # 5% per year, max 30%
    return round(base_price * (1 - discount), 2)

available_functions = {
    "check_inventory": check_inventory,
    "calculate_loyalty_discount": calculate_loyalty_discount,
}

messages = [{"role": "user", "content": "I am a customer for 5 years. What will be the final price of a laptop?"}]

# tools= accepts Python functions (schema built from type hints + docstring) or JSON-schema dicts
response = ollama.chat(model="qwen3:8b", messages=messages,
                       tools=[check_inventory, calculate_loyalty_discount])

if response.message.tool_calls:
    messages.append(response.message)                    # the model's tool request, once
    for call in response.message.tool_calls:
        result = available_functions[call.function.name](**call.function.arguments)
        messages.append({"role": "tool", "tool_name": call.function.name, "content": str(result)})

final = ollama.chat(model="qwen3:8b", messages=messages)
print(final.message.content)
Gotcha · small bug in the repo version

The repo notebook appends response['message'] inside the loop, so with two tool calls the assistant's request is added twice. Append it once before the loop, as above. The repo also writes the tool schemas by hand as JSON; passing the functions directly gives the same schema.

For one call, the ollama library is enough. Revision36 questions

Interview Q&A

Click an answer to reveal it.

Why is keyword matching a bad way to find similar items, and what replaces it?

It gives false matches (same director and actor, different story) and misses real matches (similar stories with no shared keywords). Instead, embed the content and compare vectors with cosine similarity: semantic search.

Video 12

What is a vector store and what are its core features?

A system to store and retrieve data represented as numerical vectors. Features: storage (in memory or on disk, with metadata), similarity search, indexing for fast search, and CRUD operations.

Video 12

Why can't you just use a relational database for embeddings?

Relational databases are not built to store high-dimensional vectors or to run nearest-neighbour search over millions of them. Comparing a query with every row would be far too slow.

Video 12

How does indexing speed up vector search?

For example, cluster the vectors and store each cluster's centroid. Compare the query with the centroids first, then search only the closest cluster. Far fewer comparisons, at the cost of approximate results (ANN).

Video 12

Vector store vs vector database?

A vector database is a vector store plus database features: distributed scaling, backup and restore, ACID transactions, concurrency control, authentication. FAISS is a store; Milvus, Qdrant, Weaviate and Pinecone are databases; Chroma is in between. Every vector DB is a vector store, not the other way round.

Video 12

In Chroma, a lower similarity score means what?

Closer, because similarity_search_with_score returns a distance. Use similarity_search_with_relevance_scores for a 0 to 1 score where higher is better.

Video 12

What is a retriever, and how is it different from a vector store?

A component that takes a query and returns relevant Documents from some data source. A vector store stores data; a retriever is the search interface. Retrievers are runnables, so they slot into chains, and they can sit on non-vector sources too (Wikipedia, arXiv).

Video 13

Retriever vs document loader?

A loader loads the exact source you give it. A retriever decides which content is relevant to the query.

Video 13

Explain MMR and lambda_mult.

Maximum Marginal Relevance picks each next document for being relevant to the query and different from the ones already picked, which reduces redundancy. lambda_mult = 1 is plain similarity search; 0 is maximum diversity; 0.5 is the default balance.

Video 13

When would you use a multi-query retriever?

For vague or broad queries. An LLM rewrites the query into several versions, each is searched, and the unique results are merged. Better recall, but an extra LLM call and more searches.

Video 13

What does a contextual compression retriever do?

After the base retriever fetches documents, a compressor (e.g. LLMChainExtractor) keeps only the parts relevant to the query and drops documents with nothing relevant. Less noise in the prompt, one LLM call per document.

Video 13

What is hybrid search?

Combining keyword search (BM25) with vector search, e.g. with an EnsembleRetriever. Keywords catch exact terms like product codes; vectors catch meaning.

Videos 13, 15

What is parametric knowledge?

What an LLM learned during pretraining, stored in its weights and biases. More parameters can hold more knowledge.

Video 14

Three situations where a plain LLM fails?

Questions about private data it never saw, questions about recent events after its knowledge cutoff, and hallucination (confident but wrong answers).

Video 14

Steps of supervised fine-tuning, and its problems?

Collect labelled prompt/response data, choose full fine-tuning or LoRA/QLoRA, train a few epochs, evaluate and safety-test. Problems: expensive compute, needs expert engineers, and every data change means fine-tuning again.

Video 14

What is in-context learning, and why is it called an emergent property?

Solving a task from examples in the prompt without any weight update (few-shot prompting). Emergent because it appeared on its own once models got large enough (GPT-3, 175B) without being explicitly trained for it; described in "Language Models are Few-Shot Learners".

Video 14

Define RAG and its four steps.

Retrieval-Augmented Generation gives the LLM extra relevant information at question time. Indexing (load, chunk, embed, store), Retrieval (find the top-k relevant chunks), Augmentation (put context and query into the prompt), Generation (the LLM answers from the context).

Video 14

How does RAG solve the three LLM problems?

Private data goes into the index; recent data is just re-indexed, no retraining; hallucination is reduced by grounding: "answer only from the context, otherwise say you don't know".

Video 14

RAG or fine-tuning: which would you choose?

RAG for knowledge that is private, large or changing; it is cheaper, easy to update, and can cite sources. Fine-tuning for behaviour: style, format, domain language. They can be combined.

Video 14

Why do we split documents into chunks in RAG?

The LLM's context window is limited, and embeddings of small focused chunks give much better semantic search than one vector for a whole document.

Videos 14, 15

In the YouTube RAG chain, what do RunnableParallel and RunnablePassthrough do?

RunnableParallel sends the question down two branches: the retriever plus format_docs builds "context", and RunnablePassthrough forwards the original "question". Together they produce the dict the prompt needs.

Video 15

Name the four RAGAS metrics.

Faithfulness (answer supported by context), answer relevancy (answers the question), context precision (retrieved chunks are relevant and ranked well), context recall (everything needed was retrieved).

Video 15

How would you improve a basic RAG system?

Evaluate it first (RAGAS, LangSmith). Then: better indexing (clean data, semantic chunking), pre-retrieval (query rewriting, multi-query, routing), retrieval (MMR, hybrid search, reranking), post-retrieval (contextual compression), generation (citations, guardrails), and system design (agentic or multimodal RAG).

Video 15

What is a tool in LangChain?

A Python function packaged so an LLM can understand it and call it when needed: a name, a description and an argument schema. Tools are runnables. They give the LLM "hands and legs".

Video 16

Three ways to create a custom tool?

The @tool decorator (type hints + docstring), StructuredTool.from_function with a Pydantic args_schema, or subclassing BaseTool and implementing _run.

Video 16

What does the LLM actually see of a tool?

Only its schema: name, description and JSON schema of the arguments. Never the function body. So a clear docstring and type hints decide whether it gets used correctly.

Video 16

What is a toolkit?

A bundle of related tools exposed together through get_tools(), such as a Google Drive toolkit with upload, search and read tools.

Video 16

Tool binding vs tool calling vs tool execution?

Binding registers the tools' schemas with the LLM (bind_tools). Calling: the LLM returns an AIMessage with tool_calls (name, args, id). Execution: your code runs the tool and sends back a ToolMessage with the same tool_call_id.

Video 17

Does the LLM execute the tool?

No. It only suggests the tool and the arguments. Your code or a framework (AgentExecutor, LangGraph's ToolNode) runs it.

Video 17

What is InjectedToolArg and why was it needed?

It marks a tool argument the LLM must not fill. In the currency converter, the LLM would guess the conversion rate before the rate tool had run. With InjectedToolArg the argument is hidden from the LLM and the code injects the real value from the first tool's output.

Video 17

Is LLM tool calling the same as an agent?

No. With plain tool calling the programmer decides the flow (which tool first, how outputs connect, when to stop). An agent decides that itself in a loop.

Videos 17, 18

Define an AI agent and its characteristics.

An intelligent system that takes a high-level goal and autonomously plans, decides and executes actions using tools, APIs and knowledge sources. Goal-driven, plans, tool-aware, keeps context/memory, adapts when something fails. Agent = LLM (reasoning) + tools (action).

Video 18

What is ReAct?

An agent design pattern (Reasoning + Acting, 2022 paper) where the LLM loops Thought, Action, Action Input, Observation until it can give the Final Answer. The written thoughts make the agent's behaviour transparent.

Video 18

Agent vs AgentExecutor; AgentAction vs AgentFinish?

The agent (prompt + LLM + parser) decides the next step; the AgentExecutor runs the loop and the tools. The agent returns AgentAction (tool, tool_input, log) to continue or AgentFinish (return_values, log) to stop.

Video 18

What is the agent_scratchpad?

The prompt variable holding all previous thoughts, actions and observations of the current run. It is how a stateless LLM knows what it has already done.

Video 18

What is Ollama, and when would you use it instead of an API?

A tool to download, run and manage open-source LLMs locally, behind a REST API on localhost:11434. Use it for privacy (data never leaves the machine), offline use, no per-token cost and full customisation. Limited by your RAM/VRAM; Ollama Cloud runs bigger models, at the cost of that privacy.
