1. Connecting to the server 2:56

Why a cloud VM? You rent a slice of a physical machine in a provider's data centre (~$5/month) and control it entirely through the terminal. Give a new VM a minute to finish provisioning before logging in.

ssh root@<server-ip>        # first time: type "yes" to trust the host, then the password
ssh hari@<server-ip>        # log in as a different user
Simple root passwords are fine only for throwaway demo machines. For anything real use a strong password, or better, SSH-key login.

2. Navigation & directories 4:48

ls                  # list files/dirs in current directory
ls -lart            # long list, incl. hidden (.files), oldest first — shows permissions & owner
pwd                 # print working directory, e.g. /root
cd /                # go to the root of the filesystem (like C:\ on Windows)
cd etc              # go into a folder (relative path)
cd ../              # go one level up
cd /var/lib         # jump straight there with an absolute path
mkdir hari          # make a directory
rmdir hari          # remove an EMPTY directory
Tab completion: type the first few letters and press Tab. One match completes automatically; press Tab twice to list all candidates.

Top-level folders under / you saw: bin etc home lib lost+found mnt opt root tmp usr var …

3. Files: create, copy, move, delete 11:16

touch rohan.txt                 # create an empty file
cp main.py main_backup.py       # copy (take a backup before experimenting)
mv main_backup.py backup.py     # move to a new name in the same folder = RENAME
mv backup.py rohan/backup.py    # move into another folder (the terminal's drag-and-drop)
rm main.py                      # delete a file
rm -r rohan                     # delete a directory and everything in it
rm on a directory fails ("is a directory") — you need -r. There is no recycle bin; deletes are permanent.

6. Permissions & ownership 16:02

ls -lart shows something like drwxr-xr-x 2 root root … hari:

PartMeaning
ddirectory (- = regular file)
rwx r-x r-xpermissions for owner, group, others (public)
r / w / xread (4) / write (2) / execute (1) — x is execute, not delete
root rootowner user, owner group

Add the numbers per group: 7=rwx, 6=rw-, 5=r-x, 4=r--. So 744 = owner rwx, group r, others r. (An online "chmod calculator" helps.)

chmod 744 hari                  # change permissions
chown www-data hari             # change owner user
chown www-data:www-data hari    # change owner user AND group (user:group)
chmod 777 gives everyone full access — dangerous, avoid it.

www-data is the web-server user that appears after installing Apache (apt install apache2).

7. Users, sudo & su 20:11

apt update                      # refresh package lists (Ubuntu/Debian)
apt install apache2             # install a package
useradd hari                    # add a user (adduser hari = interactive, also makes /home/hari)
passwd hari                     # set/change that user's password
usermod -aG sudo hari           # give hari sudo rights
su hari                         # switch to user hari
exit                            # go back to the previous user
su root                         # switch back to root (asks root's password)
sudo <command>                  # run ONE command with root privileges

Why sudo instead of logging in as root? Root can do anything. A normal user who must type sudo for dangerous commands gets an extra moment to think — fewer accidental disasters on a server.

8. Archives & compression 22:51

tar flagMeaning
ccreate an archive
xextract
tlist contents
vverbose (show files)
fnext argument is the archive filename
z / jcompress with gzip / bzip2
tar -cvf rohan.tar rohan.txt .wget-hsts   # bundle files into rohan.tar (archive name comes FIRST)
tar -tvf rohan.tar                         # list what's inside
tar -xvf rohan.tar                         # extract
tar -czvf backup.tar.gz folder/            # create a gzip-compressed tarball
tar -xzvf backup.tar.gz                    # extract it

gzip hari.txt       # compress → hari.txt.gz (original replaced)
gunzip hari.txt.gz  # decompress → hari.txt
In the video the first tar attempt failed because the archive name was missing — after -f always put the output name.

9. Remote copy with scp 26:40

# scp <local-file> <user>@<ip>:<destination-path>
scp secret.txt root@<other-server-ip>:/home     # asks the OTHER server's password
scp root@<ip>:/home/secret.txt .               # reverse: download to current dir
scp -r myfolder root@<ip>:/root                # copy a whole folder

11. Processes & monitoring 15:30

15. Text processing 36:05

ls | tee file.txt       # show output on screen AND write it to file.txt
sort hari.txt           # print lines sorted (a c b d → a b c d)
uniq hari.txt           # drop ADJACENT duplicate lines
sort hari.txt | uniq    # remove all duplicates (sort first!)
head hari.txt           # first 10 lines   (head -n 5 for 5)
tail hari.txt           # last 10 lines
tail -n 2 -f hari.txt   # last 2 lines, then keep watching live (logs!) — Ctrl+C to stop
uniq only removes duplicates that sit next to each other — that's why the video's blank line survived. Pipe through sort first for true de-duplication.
