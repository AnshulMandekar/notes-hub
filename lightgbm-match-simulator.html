Watch LightGBM decide, one tree at a time

This is a real LightGBM model trained on every Vermont business in the challenge's training data, cleaned with the project's own code. It uses 8 clues and very small trees so you can read each tree. Pick a pair of records, then add trees one by one and watch the score change.

How one tree is built

  1. Every pair starts with the same score: the share of training pairs that are true matches.
  2. For each pair, LightGBM measures how wrong the current score is: pushed too low for a true match, too high for a non-match.
  3. It tries every clue and every cut-off and picks the question that best separates the pairs that need a push up from those that need a push down. It keeps splitting the most useful group until the tree has 4 leaves.
  4. Each leaf gets a number: roughly the average correction its pairs need, times the learning rate (0.3). A pair's score moves by the number of the leaf it lands in.
  5. The next tree repeats this on what is still wrong. Training stops when 15 more trees fail to improve the score on held-out businesses.

Which clues the trees used most (share of total gain)

“Lead over next candidate” leads by far: a pair is much more believable when it clearly beats every other candidate for the same record. The real project has eight features of this kind (the “margins”).

Where this small model fails

In the held-out Vermont pairs there are 51 decoys that are the top search result, have the business's house number and a near-identical address, and differ in name words. This 8-clue model accepts 30 of them at 0.5 and 13 even at 0.85. The two mistakes in the picker show the problem from both sides: a real match whose house number changed from 15 to 3, and a decoy that swaps one word and cuts the house number the way noise does (“Brown Dental LLC, 74 Newbury Center Road” vs “Brown Popular LLC, 741 Newbury Center Road”).

The full project adds exactly the clues that target this: word-by-word alignment with the rarity of every unmatched word, house-number closeness, a second model that checks each record against its siblings, and a stricter bar for next-door house numbers.
