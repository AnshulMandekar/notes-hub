Q01 · Basic1:11

What is Java, and why isn't it "pure" object-oriented?

Java is a class-based, object-oriented language built to be simple and portable. Its motto is "Write Once, Run Anywhere" (WORA): you compile once, and the same compiled file runs on Windows, Mac or Linux without recompiling. That's why big companies use it for enterprise apps.

A pure OOP language would make everything an object. Java doesn't, for two reasons:

1. Primitive types

int, char, double, boolean… are plain values, not objects. They have no methods. 5.toString() doesn't work.

2. The static keyword

Static methods and variables belong to the class. You can use them without creating any object, so you skip the "everything goes through objects" rule.

NotPureOOP.javaran
int a = 5;                        // primitive: no object, no methods
Integer b = 5;                    // wrapper object around 5
System.out.println(b.toString()); // works: b is an object
// System.out.println(a.toString()); // compile error: int has no methods

System.out.println(Math.max(3, 7)); // static method: no "new Math()" needed
Interview

Say both reasons: primitives and static members. Then add that wrapper classes (Integer, Float) exist to turn primitives into objects, but Java still lets you use raw primitives directly.

Q02 · Basic2:22

JDK, JRE and JVM: how a Java program runs

Running Java takes two steps: compile, then execute.

  1. You write Example.java (human-readable source code).
  2. Compile: javac (part of the JDK) turns it into bytecode, stored in Example.class. Bytecode isn't tied to any OS.
  3. Execute: the JVM loads the bytecode, links it with system libraries, and runs it on your machine.
PieceFull nameJob (simple words)
JDKJava Development KitThe full toolbox for developers. Includes the compiler javac plus everything in the JRE.
JREJava Runtime EnvironmentWhat you need to run a compiled program: the JVM plus the standard libraries.
JVMJava Virtual MachineThe "engine" that actually executes bytecode. There's a different JVM for each OS, which is what makes bytecode portable.
terminal
javac Example.java   # compile: creates Example.class (bytecode)
java Example         # run: the JVM executes the bytecode
java Example.java    # Java 11+: compile + run a single file in one step
Gotcha

The video says the JVM runs bytecode "line by line". That's only half true. The JVM starts by interpreting bytecode, but the JIT (Just-In-Time) compiler turns frequently used ("hot") code into native machine code while the program runs. That's why Java is fast. Also, since Java 11, Oracle no longer ships a separate JRE download. You install a JDK.

Main features of Java

Simple

Clean syntax. No pointers and no manual memory freeing, so whole classes of bugs never happen.

Object-oriented

Code is organised into classes and objects, which makes it easier to maintain.

Bytecode + JVM = runs anywhere (WORA).

Q04 · Basic4:56

What is the Java String Pool?

The string pool is a special area inside heap memory. Think of it as a library of string values. When you write a string literal like "abc", Java first checks the pool:

  • Already there? You get a reference to the existing copy. No new memory is used.
  • Not there? Java adds it to the pool, then gives you the reference.
  • new String("abc") skips the pool and always creates a fresh object on the regular heap.
StringPool.javaran
public class StringPool {
    public static void main(String[] args) {
        String a = "abc";               // goes to the string pool
        String b = "abc";               // reuses the SAME pooled object
        String c = new String("abc");   // forces a NEW object on the heap

        System.out.println(a == b);       // true  (same reference)
        System.out.println(a == c);       // false (different objects)
        System.out.println(a.equals(c));  // true  (same characters)
        System.out.println(a == c.intern()); // true (intern() returns the pooled copy)
    }
}

Why bother? Programs use the same strings again and again. Sharing one copy saves memory, and comparing references is very fast.

Gotcha

== compares references ("are these the same object?"). .equals() compares content ("same characters?"). Always use .equals() to compare strings. == only happens to work for pooled literals.

Interview

"How many objects does new String("abc") create?" Up to two: one "abc" in the pool (if it wasn't there already) and one new object on the heap.

Q05 · Basic5:54

Wrapper classes, and why we need them

A wrapper class "wraps" a primitive value inside an object. Each primitive has one:

Primitivebyteshortintlongfloatdoublecharboolean
WrapperByteShortIntegerLongFloatDoubleCharacterBoolean

Why we need them

  • Collections only store objects. ArrayList<int> isn't allowed. You write ArrayList<Integer>.
  • Useful methods: Integer.parseInt("42"), Integer.valueOf(5), x.toString(), Integer.MAX_VALUE.
  • They can be null, which is handy for "no value yet" (e.g. a database column that's empty).

Autoboxing and unboxing

Wrappers.javaran
List<Integer> marks = new ArrayList<>();
marks.add(90);                    // autoboxing: int 90 -> Integer

Integer boxed = 5;                // autoboxing
int unboxed = boxed;              // unboxing: Integer -> int

int n = Integer.parseInt("42");   // String -> int
String s = Integer.toString(42);  // int -> String
System.out.println(n + unboxed);  // 47
Gotcha

Unboxing a null wrapper throws a NullPointerException: Integer x = null; int y = x; 💥. Also, don't compare wrappers with ==. Integer caches only −128 to 127, so Integer a=1000, b=1000; a==b is false. Use .equals().

Q06 · Scenario7:01

Online bookstore: picking the right collection

The scenario: you need (1) a list of all books, (2) a set of unique genres, (3) a mapping of each author to their books. The Java Collections Framework has a ready-made structure for each.

Bookstore.javaran
import java.util.*;

// 1. All books: a dynamic array that grows as we add
List<String> books = new ArrayList<>();
books.add("Dune");
books.add("Emma");

// 2. Unique genres: duplicates are silently ignored
Set<String> genres = new HashSet<>();
genres.add("Sci-Fi");
genres.add("Classic");
genres.add("Sci-Fi");               // ignored -> size is still 2

// 3. Author -> their books (like a dictionary)
Map<String, List<String>> byAuthor = new HashMap<>();
byAuthor.computeIfAbsent("Austen", k -> new ArrayList<>()).add("Emma");
byAuthor.computeIfAbsent("Austen", k -> new ArrayList<>()).add("Persuasion");

System.out.println(byAuthor.get("Austen"));   // [Emma, Persuasion]

Why it matters: collections give you tested, built-in methods to add, remove and search. You don't write those yourself, so the code is shorter and easier to maintain.

Extra

Need sorted order? TreeSet / TreeMap. Need insertion order? LinkedHashSet / LinkedHashMap. Speed: ArrayList.get(i) is O(1). HashSet.contains and HashMap.get are O(1) on average.

Q07 · Basic8:35

this vs super

this = "me" (current object)

Use it to tell a field apart from a parameter with the same name (this.name = name), to call another constructor of the same class (this(...)), or to pass the current object somewhere.

super = "my parent"

Use it to call the parent's constructor (super(...), which must be the first line), or the parent's version of a method or field (super.makeSound()).

ThisSuper.javaran
class Animal {
    String name;

    Animal(String name) {
        this.name = name;          // this.name = field, name = parameter
    }

    void makeSound() {
        System.out.println(name + " makes a sound");
    }
}

class Dog extends Animal {
    Dog(String name) {
        super(name);               // call the parent constructor (must be first)
    }

    @Override
    void makeSound() {
        super.makeSound();         // run the parent's version first...
        System.out.println(name + " barks");   // ...then add Dog behaviour
    }
}

// new Dog("Bruno").makeSound();
// Bruno makes a sound
// Bruno barks
Gotcha

Neither this nor super works inside a static method, because there is no "current object" there.

Q09 · Advanced11:05

Constructors and their types

Analogy: a new phone asks you to pick a language and connect to Wi-Fi before you can use it. A constructor is that first-time setup for an object. It runs automatically when you write new.

Rules for a constructor

  • It has the same name as the class.
  • It has no return type, not even void.
  • It's called automatically by new.

Default (no-arg) constructor

Takes no arguments. If you write no constructor at all, Java adds an empty one for you.

Parameterized constructor

Takes arguments, so each object can start with different values.

Constructors.javaran
class Bike {
    Bike() {                                   // default / no-arg constructor
        System.out.println("Bike is created");
    }
}

class Car {
    String model;
    int year;

    Car(String m, int y) {                     // parameterized constructor
        model = m;
        year = y;
    }

    void display() {
        System.out.println("Model: " + model + ", Year: " + year);
    }
}

new Bike();                                    // Bike is created
Car car1 = new Car("Tesla Model Y", 2022);
car1.display();                                // Model: Tesla Model Y, Year: 2022
Gotcha

Once you write any constructor (e.g. Car(String, int)), Java stops adding the free default one. After that, new Car() is a compile error unless you also write Car() {} yourself.

Extra

Interviewers also ask about constructor overloading (several constructors with different parameters) and constructor chaining (this(...) calls a sibling constructor, super(...) calls the parent's). Java has no built-in "copy constructor" like C++, but you can write one: Car(Car other).

Q10 · Advanced13:37

StringBuffer vs StringBuilder

A String can't be changed once it's created. If you need to change text many times (in a loop, say), use a mutable class instead: StringBuffer or StringBuilder. Both have the same methods (append, insert, reverse, delete…). The only difference is thread safety.

StringBufferStringBuilder
Thread safe?Yes (methods are synchronized)No
SpeedSlower (locking costs time)Faster
Added inJava 1.0Java 5
Use whenSeveral threads change the same objectSingle thread (almost always)
Builders.javaran
StringBuffer sbf = new StringBuffer("Hello");
sbf.append(" World");               // modifies the same object, thread-safe
System.out.println(sbf);            // Hello World

StringBuilder sb = new StringBuilder("Hello");
sb.append(" Java").reverse();       // methods can be chained
System.out.println(sb);             // avaJ olleH

// Why not plain String in a loop? Each + makes a brand-new String object.
StringBuilder out = new StringBuilder();
for (int i = 0; i < 5; i++) out.append(i);   // one object reused
System.out.println(out);            // 01234
Gotcha

At one point the video says StringBuilder is "more efficient than string builder". It means StringBuilder is faster than StringBuffer. Default answer in interviews: "Use StringBuilder unless the object is shared between threads."

Q11 · Advanced16:10

Abstract class vs interface

Both let you say "every subclass must implement this method". The difference is in what else they allow. A simple way to think about it: an abstract class is a half-built template, and an interface is a contract / list of abilities.

Abstract classInterface
MethodsAbstract and normal (with body)Abstract by default (+ default/static since Java 8)
InheritanceSingle: extends one classMultiple: implements A, B, C
VariablesAny kind: instance, static, finalOnly public static final constants
ConstructorYesNo
Can extendA class, and implement interfacesOnly other interfaces
Use whenRelated classes share code and state ("is-a")Unrelated classes share an ability ("can-do")
Shapes.javaran
abstract class Shape {
    abstract void draw();                    // no body: subclasses MUST write it

    void move() {                            // normal method: inherited as-is
        System.out.println("Moving the shape");
    }
}

class Circle extends Shape {
    void draw() { System.out.println("Drawing a circle"); }
}

interface Drawable {
    int MAX_SIZE = 100;                      // automatically public static final
    void draw();                             // automatically public abstract
}

interface Resizable { void resize(int pct); }

class Rectangle implements Drawable, Resizable {   // multiple interfaces: OK
    public void draw()          { System.out.println("Drawing a rectangle"); }
    public void resize(int pct) { System.out.println("Resized by " + pct + "%"); }
}

// new Shape();   // compile error: abstract classes can't be instantiated
Gotcha

The video says interfaces can have "only abstract methods" and "can't provide implementation". That was true before Java 8. Modern Java lets interfaces have default methods (with a body), static methods, and (Java 9+) private methods. Mention this in an interview. It shows you know current Java.

Q12 · Advanced18:36

Method overloading, and can we overload main?

Overloading = same method name, different parameters in the same class. The parameters must differ in number, type, or both (order of types counts too). It's compile-time polymorphism: the compiler picks the right version from the arguments you pass.

Can we overload main?

Yes. But the JVM always starts the program from exactly public static void main(String[] args). Your other main versions are ordinary methods. They only run if you call them yourself.

Overloading.javaran
public class Overloading {
    public static void main(int x) {              // overloaded main #1
        System.out.println("main(int): " + x);
    }

    public static void main(double d) {           // overloaded main #2
        System.out.println("main(double): " + d);
    }

    public static void main(String[] args) {      // the REAL entry point
        main(5);       // main(int): 5
        main(3.14);    // main(double): 3.14
    }
}
Gotcha

Changing only the return type is NOT overloading. int f() and double f() together is a compile error, because the compiler can't tell which one f() means.

Q13 · Advanced21:08

Method overriding, and the rules for static and private methods

Overriding = a subclass gives its own version of a method that the parent already has, with the same name and same parameters. It's runtime polymorphism: Java picks the method based on the actual object, not the variable type.

Overriding.javaran
class Animal {
    void move() { System.out.println("Animal is moving"); }
    void eat()  { System.out.println("Animal is eating"); }
}

class Dog extends Animal {
    @Override                      // asks the compiler to check that we really override
    void move() { System.out.println("Dog is running"); }
}

Animal a = new Dog();
a.move();   // Dog is running    (overridden)
a.eat();    // Animal is eating  (inherited)

Rules / restrictions

  • Same signature: same name and same parameter list. The return type must be the same or a subtype ("covariant").
  • Can't reduce visibility: a public method can't become protected/private in the child. Making it more visible is fine.
  • static methods can't be overridden. Overriding needs a runtime object, and static methods belong to the class. A static method with the same name in the child hides the parent's (method hiding).
  • private methods can't be overridden. The child can't even see them. A same-named method in the child is a brand-new, unrelated method.
  • final methods can't be overridden.
  • Checked exceptions: the child can't throw broader checked exceptions than the parent.
OverloadingOverriding
WhereSame classParent → child class
ParametersMust differMust be the same
PolymorphismCompile time (static)Runtime (dynamic)
static / private?Can be overloadedCan't be overridden
Q14 · Advanced23:23

How exceptions are handled in Java

Analogy: you're watching YouTube and the Wi-Fi drops. The app doesn't crash. It shows "No internet" and carries on. Exception handling does the same for your program: when a runtime error happens, you catch it and keep the program's normal flow going.

BlockWhat it does
tryWraps code that might throw an exception.
catchCatches and handles a specific exception type. You can have several, ordered from specific to general.
finallyAlways runs, exception or not. Use it for cleanup (close files, DB connections).
throwThrows an exception yourself: throw new IllegalArgumentException("bad age").
throwsDeclares in a method signature that it may throw: void read() throws IOException.
Exceptions.javaran
try {
    int result = 10 / 0;                       // throws ArithmeticException
    System.out.println("never printed");
} catch (ArithmeticException e) {
    System.out.println("Can't divide by zero"); // handled here
} catch (Exception e) {                         // general fallback goes LAST
    System.out.println("Something else went wrong");
} finally {
    System.out.println("This block always runs");
}
// Output:
// Can't divide by zero
// This block always runs
Extra

Checked vs unchecked: checked exceptions (IOException, SQLException) must be caught or declared, and the compiler enforces it. Unchecked ones (RuntimeException and its subclasses: NullPointerException, ArithmeticException, ArrayIndexOutOfBoundsException) don't have to be. Error (like OutOfMemoryError) is a serious JVM problem you normally don't catch.

Q15 · Advanced25:41

Life cycle of a thread

A thread is a lightweight unit of work that runs in parallel with other threads. Like a process in an operating system, it moves through stages from birth to death.

StateMeaning
NewThread object created, start() not called yet.
Runnablestart() called. Ready to run, waiting for the CPU scheduler.
RunningHas the CPU and is executing run().
Blocked / Waiting / SleepingPaused: waiting for I/O, a lock, sleep(), wait() or join().
Terminatedrun() finished (or threw an exception). Can't be restarted.
ThreadStates.javaran
Thread t = new Thread(() -> {
    try { Thread.sleep(100); } catch (InterruptedException e) { }
});
System.out.println(t.getState());  // NEW
t.start();
System.out.println(t.getState());  // RUNNABLE
Thread.sleep(20);
System.out.println(t.getState());  // TIMED_WAITING (sleeping)
t.join();                          // wait for it to finish
System.out.println(t.getState());  // TERMINATED
Gotcha

Java's real Thread.State enum has 6 values: NEW, RUNNABLE, BLOCKED, WAITING, TIMED_WAITING, TERMINATED. There's no separate "RUNNING". Java counts running as part of RUNNABLE. The 5-stage picture above is the textbook/OS view. Know both. Also, calling start() twice throws IllegalThreadStateException.

Q16 · Advanced26:50

Singleton class: what it is and how to make one

A singleton class allows only one object in the whole program. However many times you ask for it, you get the same instance. Useful for shared resources like a database connection pool, a logger or app config. Several copies there would waste memory or cause conflicts.

3 steps to build one

  1. Private constructor: nobody outside can call new.
  2. Static instance variable: holds the one object, shared across all calls.
  3. Static getInstance() method: the global access point. Creates the object only if it doesn't exist yet, then always returns it.
Singleton.javaran
class Singleton {
    private static Singleton instance;          // step 2: the one shared object

    private Singleton() { }                     // step 1: no "new" from outside

    public static synchronized Singleton getInstance() {   // step 3
        if (instance == null) {
            instance = new Singleton();         // created only on first call (lazy)
        }
        return instance;
    }
}

Singleton s1 = Singleton.getInstance();
Singleton s2 = Singleton.getInstance();
System.out.println(s1 == s2);   // true: same object
Gotcha

Without synchronized, two threads could both see instance == null at the same moment and create two objects. Thread-safe options: (a) synchronized as above, (b) eager init, private static final Singleton INSTANCE = new Singleton();, or (c) the best one, an enum: enum Config { INSTANCE; }. An enum is thread-safe and also safe against reflection and serialization.

Aggregation vs composition

Both describe a "has-a" relationship between objects. The question is: can the child live without the parent?

AggregationComposition
Relationship"has-a" (loose)"part-of" (tight)
Child without parent?Yes, it has its own life cycleNo, it's destroyed with the parent
Who creates the child?Usually created outside, then passed inThe parent creates it inside
ExampleDepartment–Student, Team–PlayerLibrary–Book, House–Room, Car–Engine
Relations.javaran
// AGGREGATION: students are created outside and handed to the department
class Student { String name; Student(String n) { name = n; } }

class Department {
    List<Student> students;
    Department(List<Student> students) { this.students = students; }
}

List<Student> list = List.of(new Student("Asha"), new Student("Ravi"));
Department cs = new Department(list);

}

Q18 · Advanced30:14

Anonymous inner class

A class with no name that you declare and create in a single expression. Think of it as a "disposable tool": a one-time implementation of an interface or subclass of a class, used right where it's needed. You skip writing a separate class file.

AnonymousDemo.javaran
interface Age {
    void getAge();
}

public class AnonymousDemo {
    public static void main(String[] args) {
        int years = 21;                        // effectively final: never reassigned

        Age obj = new Age() {                  // "new Age() {...}" = anonymous class
            @Override
            public void getAge() {
                System.out.println("Age is " + years);   // can read local vars
            }
        };

        obj.getAge();                          // Age is 21
    }
}

Key points

  • No name, so it can't have a constructor.
  • Exactly one object of it is created, right there.
  • It can either implement one interface or extend one class.
  • It can use the surrounding method's local variables only if they're final or effectively final (never reassigned).
Extra

Since Java 8, if the interface has only one abstract method (a "functional interface"), a lambda is shorter: Age obj = () -> System.out.println("Age is 21");. Anonymous classes are still needed when the interface has several methods, or when you need fields or state.

Q19 · Advanced33:09

Implicit vs explicit type conversion

Analogy: pouring water from a small glass into a big one is automatic and safe. Pouring from a big glass into a small one might spill, so you have to do it carefully and on purpose.

Implicit (widening)Explicit (narrowing / casting)
Who does itThe compiler, automaticallyYou, with (type)
DirectionSmaller → larger typeLarger → smaller type
Data loss?NoPossibly (decimals cut off, overflow)
AdvantageConvenient, no extra codeControl and clarity: you show you meant it
Casting.javaran
// Implicit: int fits easily into double
int num = 10;
double d = num;                 // 10.0, no cast needed

// Explicit: double -> int must be cast manually
double bigNum = 9.78;
int n = (int) bigNum;           // 9, the decimal part is CUT, not rounded

// Data loss example: int too big for byte
int big = 300;
byte b = (byte) big;            // 44, because 300 wraps around (300 - 256)

System.out.println(d + " " + n + " " + b);   // 10.0 9 44
Gotcha

Casting to int truncates (9.78 → 9). It doesn't round. Use Math.round(9.78) if you want 10.

Q20 · Advanced34:58

The volatile keyword

For speed, each thread may keep its own cached copy of a variable. So if thread 1 changes flag, thread 2 might keep reading its old cached value for a while. Marking a variable volatile tells the JVM to always read it from and write it to main memory, so every thread sees the latest value straight away.

VolatileDemo.javaran
public class VolatileDemo {
    private static volatile boolean running = true;   // try removing "volatile"

    public static void main(String[] args) throws InterruptedException {
        Thread worker = new Thread(() -> {
            while (running) { }          // keeps checking the flag
            System.out.println("Worker saw running = false, stopping");
        });
        worker.start();

        Thread.sleep(500);
        running = false;                 // main thread flips the flag
        worker.join();                   // without volatile this could loop forever
    }
}
Gotcha

The video calls x = x + 1 an "atomic operation". It isn't. It's three steps (read, add, write), and two threads can interleave them and lose an update. volatile gives visibility only, not atomicity. So a volatile int count; count++ shared by threads is still buggy. Use AtomicInteger.incrementAndGet() or synchronized for that. Good uses of volatile: status flags like running/stop, and the double-checked-locking singleton.

Access specifiers (modifiers) and their purpose

Q23 · Advanced39:08

Are final, finally and finalize the same?

No. They only sound alike. They do completely different jobs.

final (keyword) = restriction

Variable: can't be reassigned.
Method: can't be overridden.
Class: can't be extended (e.g. String).

finally (block) = always-run cleanup

Used with try/catch. It runs whether or not an exception happened. Good for closing files and DB connections.

finalize() (method) = before garbage collection

Called by the garbage collector just before an object is destroyed. Deprecated, so don't use it.

FinalFinallyFinalize.javaran
// final: restriction
final int x = 10;
// x = 20;                    // COMPILE ERROR: cannot assign a value to final variable x

final class Constants { }     // nobody can extend this class

// finally: always runs
try {
    int y = 5 / 0;            // exception
} catch (ArithmeticException e) {
    System.out.println("Caught: " + e.getMessage());
} finally {
    System.out.println("finally runs regardless");   // also runs if y = 20 / 5
}

// Modern replacement for "cleanup" code: try-with-resources
try (var reader = new java.io.BufferedReader(new java.io.FileReader("data.txt"))) {
    System.out.println(reader.readLine());
} catch (java.io.IOException e) {
    System.out.println("Could not read file");
}   // reader.close() is called automatically here
Interview

One-line summary: final restricts, finally cleans up after try/catch, finalize cleans up before garbage collection. Then add: "finalize() has been deprecated since Java 9 because there's no guarantee when, or even whether, it runs. Use try-with-resources or Cleaner instead."

Q24 · Coding41:43

Toggle the case of every character

Task: change uppercase letters to lowercase and lowercase to uppercase. "sTrInG" → "StRiNg".

Approach (pseudo code)

  1. Read the input string.
  2. Create an empty StringBuilder for the result.
  3. Loop over each character: uppercase → append its lowercase, lowercase → append its uppercase, anything else → append as-is.
  4. Print the result.
ToggleCase.javaran
import java.util.Scanner;

public class ToggleCase {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        System.out.print("Enter a string: ");
        String input = sc.nextLine();
        sc.close();

        StringBuilder result = new StringBuilder();
        for (char ch : input.toCharArray()) {
            if (Character.isUpperCase(ch)) {
                result.append(Character.toLowerCase(ch));   // A -> a
            } else if (Character.isLowerCase(ch)) {
                result.append(Character.toUpperCase(ch));   // a -> A
            } else {
                result.append(ch);                          // digits, spaces stay the same
            }
        }
        System.out.println("Toggled: " + result);
    }
}
// Input:  sTrInG Java
// Output: Toggled: StRiNg jAVA

Complexity: O(n) time, O(n) space for the result.

Interview

Why StringBuilder and not result += ch? Strings are immutable, so each += creates a new String object. That's O(n²) work in a loop. StringBuilder appends in place (see Q10).

Q25 · Coding44:14

Count how many times digit d occurs in number n

Task: the user enters n = 1234465 and d = 4. Answer: 4 appears 2 times.

The trick: peel digits off with % and /

  • n % 10 gives the last digit (1234465 % 10 = 5).
  • n / 10 drops the last digit (1234465 / 10 = 123446).
  • Repeat while n > 0, counting each time the last digit equals d.
CountDigit.javaran
import java.util.Scanner;

public class CountDigit {
    static int countDigitOccurrences(long n, int d) {
        n = Math.abs(n);                 // handle negative numbers
        if (n == 0) return d == 0 ? 1 : 0;  // the number 0 has one digit: 0
        int count = 0;
        while (n > 0) {
            if (n % 10 == d) count++;    // last digit
            n = n / 10;                  // drop the last digit
        }
        return count;
    }

    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        System.out.print("Enter number n: ");
        long n = sc.nextLong();
        System.out.print("Enter digit d: ");
        int d = sc.nextInt();
        sc.close();
        System.out.println("Digit " + d + " occurs " + countDigitOccurrences(n, d) + " times");
    }
}
// Input: 1234465, 4  ->  Digit 4 occurs 2 times

Complexity: O(number of digits) = O(log₁₀ n) time, O(1) space.

Gotcha

The video's simple version gives the wrong answer for n = 0, d = 0 (the loop never runs, so it returns 0), and it breaks for negative n. The two extra lines at the top of the function fix both. Interviewers love asking about these edge cases.

Q26 · Coding46:18

Reverse an array using recursion (no extra array)

Task: [1, 10, 12, 13] → [13, 12, 10, 1], in place (O(1) extra space, not counting the recursion stack).

Approach: two pointers that walk inward

  1. Function takes (arr, start, end).
  2. Base case: if start >= end, stop. Zero or one element is left, so there's nothing to swap.
  3. Swap arr[start] and arr[end].
  4. Recurse on the inner part: reverse(arr, start + 1, end - 1).
  5. Start the first call with reverse(arr, 0, arr.length - 1).
ReverseArray.javaran
import java.util.Arrays;

public class ReverseArray {
    static void reverse(int[] arr, int start, int end) {
        if (start >= end) return;        // base case: 0 or 1 element left
        int temp = arr[start];           // swap the two ends
        arr[start] = arr[end];
        arr[end] = temp;
        reverse(arr, start + 1, end - 1); // move both pointers inward
    }

    public static void main(String[] args) {
        int[] arr = {1, 10, 12, 13};
        reverse(arr, 0, arr.length - 1);
        System.out.println(Arrays.toString(arr));   // [13, 12, 10, 1]
    }
}

Complexity: O(n) time (n/2 swaps). Extra space is O(1) if you ignore the call stack, as the question says. Honestly it's O(n) stack frames, so a loop version is safer for huge arrays (no StackOverflowError).

Q27 · Coding48:59

Check if two strings are anagrams

Anagrams have the same letters with the same counts, just in a different order. "act" and "cat": a=1, c=1, t=1 in both, so they're anagrams.

Approach (sorting)

  1. If the lengths differ → not anagrams. Stop early.
  2. Turn both strings into char[] arrays.
  3. Sort both arrays alphabetically.
  4. If the sorted arrays are equal → anagrams.
Anagram.javaran
import java.util.Arrays;

public class Anagram {
    static boolean isAnagram(String s1, String s2) {
        if (s1.length() != s2.length()) return false;  // different length -> can't be anagrams
        char[] a = s1.toCharArray();
        char[] b = s2.toCharArray();
        Arrays.sort(a);                                 // "act" -> [a, c, t]
        Arrays.sort(b);                                 // "cat" -> [a, c, t]
        return Arrays.equals(a, b);
    }

    public static void main(String[] args) {
        System.out.println(isAnagram("act", "cat"));     // true
        System.out.println(isAnagram("listen", "silent")); // true
        System.out.println(isAnagram("java", "jazz"));   // false
    }
}

Complexity: O(n log n) because of sorting.

Extra

The video mentions a map-based version but doesn't show it. Here's the faster O(n) counting version for lowercase a–z. Interviewers often ask for it as a follow-up:

AnagramCount.javaran
static boolean isAnagramFast(String s1, String s2) {
    if (s1.length() != s2.length()) return false;
    int[] count = new int[26];
    for (int i = 0; i < s1.length(); i++) {
        count[s1.charAt(i) - 'a']++;     // +1 for letters in s1
        count[s2.charAt(i) - 'a']--;     // -1 for letters in s2
    }
    for (int c : count) if (c != 0) return false;   // any leftover = mismatch
    return true;
}
Q28 · Coding51:51

First and last index of an element (linear time, no extra space)

Task: in [1, 2, 3, 4, 3, 5, 3, 6], find where 3 first and last appears. Answer: first = 2, last = 6.

Approach

  1. Set first = -1 and last = -1 ("not found yet").
  2. Loop through the array once.
  3. When you find the target: set first only if it's still −1, and update last every time.
  4. After the loop: if first == -1, the target isn't there. Otherwise print both.
FirstLast.javaran
public class FirstLast {
    public static void main(String[] args) {
        int[] arr = {1, 2, 3, 4, 3, 5, 3, 6};
        int target = 3;
        int first = -1, last = -1;            // -1 means "not found yet"

        for (int i = 0; i < arr.length; i++) {
            if (arr[i] == target) {
                if (first == -1) first = i;    // set only the first time
                last = i;                      // keep updating every time
            }
        }

        if (first == -1) {
            System.out.println(target + " is not in the array");
        } else {
            System.out.println("First index: " + first + ", Last index: " + last);
        }
    }
}
// Output: First index: 2, Last index: 6
Extra

The question says "consider 1-based index". If so, print first + 1 and last + 1. Follow-up: if the array is sorted, you can do it in O(log n) with two binary searches (one for the leftmost match, one for the rightmost).

Q29 · Advanced54:40

Why are Strings immutable in Java (besides security)?

Immutable = once created, a String object can never change. Methods like toUpperCase() or concat() return a new String. There are three practical reasons for this design:

1. String pool optimization

Many variables share one pooled "abc" (see Q4). If strings could change, editing one variable would quietly change all the others pointing to the same object and break the program. Sharing is only safe because strings never change.

2. Thread safety

Strings get passed between threads all the time. Since an immutable object's state can't change, any number of threads can read it at once without synchronized. That makes the code simpler and less error-prone.

3. Reliable hash-based collections

Strings are the most common HashMap key. The map files a key in a bucket by its hash code. If the string could change after insertion, its hash would change too, and map.get() would look in the wrong bucket and fail. Immutability also lets String cache its hash code.

Immutable.javaran
String s = "hello";
s.toUpperCase();              // returns a NEW string, which we ignore
System.out.println(s);        // hello  (unchanged!)

s = s.toUpperCase();          // re-point s to the new object
System.out.println(s);        // HELLO  (the old "hello" object still exists, unchanged)
Interview

Summary line: "Immutability gives memory optimization (string pool), thread safety, and reliable data management (stable hash codes)." Also mention that String is a final class, so nobody can subclass it and add mutability.

Q30 · Advanced57:03

Deep copy vs shallow copy

Shallow copy: shared cupboard 🗄️

Copies the outer object, but the objects inside it are still shared (only the references are copied). Two friends sharing one cupboard: if one adds something, the other sees it too.

Deep copy: separate piggy banks 🐷🐷

Copies the object and everything inside it. Each friend has their own piggy bank, so coins added to one don't show up in the other. More memory, fully independent.

Shallow copyDeep copy
CopiesOuter object; inner objects are shared referencesOuter object + all inner objects
MemoryLess (inner objects not duplicated)More (everything duplicated)
Changing the copy's inner dataAlso changes the original ⚠Original stays safe ✅
SpeedFasterSlower
Default clone()Yes, Object.clone() is shallowYou must write it yourself
CopyDemo.javaran
public class CopyDemo {
    public static void main(String[] args) {
        Person original = new Person("Asha", new Address("Pune"));

        Person shallow = original.shallowCopy();
        shallow.address.city = "Delhi";
        System.out.println(original.address.city);   // Delhi  <- original changed too!

        original.address.city = "Pune";              // reset
        Person deep = original.deepCopy();
        deep.address.city = "Mumbai";
        System.out.println(original.address.city);   // Pune   <- original is safe
    }
}

class Address {
    String city;
    Address(String city) { this.city = city; }
}

class Person {
    String name;
    Address address;
    Person(String name, Address address) { this.name = name; this.address = address; }

    Person shallowCopy() {
        return new Person(name, address);                    // new Person, SAME Address
    }

    Person deepCopy() {
        return new Person(name, new Address(address.city));  // new Person, NEW Address
    }
}
Gotcha

The video's examples are really two separate new objects (labelled "deep") and reference assignment, A obj2 = obj1; (labelled "shallow"). Plain assignment isn't a copy at all. It's just a second name for the same object. A true shallow copy creates a new outer object that still shares the inner ones, as in the code above. The difference only shows when the object contains other objects.

Quick revision quiz

Click a blurred answer to reveal it.

Two reasons Java isn't pure OOP?

Primitive types (int, char…) aren't objects, and static members can be used without any object.

JDK vs JRE vs JVM in one line each?

JDK = tools to develop (javac) + JRE. JRE = JVM + libraries to run. JVM = executes bytecode (interpreter + JIT).

What does "abc" == new String("abc") return?

false: the literal is in the string pool, new creates a separate heap object. Use .equals() for content.

Why can't you write ArrayList<int>?

Collections store only objects. Use the wrapper Integer. Autoboxing converts automatically.

List vs Set vs Map for the bookstore?

ArrayList for all books (ordered, duplicates), HashSet for unique genres, HashMap for author → books.

Can a static method use this?

No. There's no current object in a static context.

What happens to the default constructor once you write a parameterized one?

Java no longer adds it. new X() fails unless you write X() yourself.

StringBuffer or StringBuilder by default?

StringBuilder (faster, not synchronized). Use StringBuffer only when several threads modify the same object.

Can interfaces have method bodies?

Yes, since Java 8: default and static methods. Java 9 adds private methods.

Can you overload main? Override a static method?

Overload main: yes, but the JVM only calls main(String[]). Override static: no, it's method hiding.

Overloading vs overriding: which is runtime polymorphism?

Overriding (decided by the actual object at runtime). Overloading is compile time.

When does finally run?

Always, whether or not an exception was thrown or caught (unless the JVM exits, e.g. System.exit()).

Name Java's 6 thread states.

NEW, RUNNABLE, BLOCKED, WAITING, TIMED_WAITING, TERMINATED.

3 ingredients of a singleton?

Private constructor, private static instance, public static getInstance(). Make it thread-safe (synchronized / eager / enum).

Aggregation or composition: Library and Book (per the video)?

Composition: books are destroyed with the library. Department–Student is aggregation.

Can an anonymous class have a constructor?

No. It has no name. It can only use effectively final local variables.

What does (int) 9.78 give?

9. Narrowing casts truncate, they don't round.

Does volatile make count++ thread-safe?

No. It only guarantees visibility. Use AtomicInteger or synchronized for atomic updates.

How many access levels are there?

Four: public, protected, default (package-private), private.

final vs finally vs finalize?

Restriction keyword / always-run block after try-catch / deprecated method called before garbage collection.

How do you get the last digit of n and remove it?

n % 10 gives the last digit, n / 10 drops it.

Anagram check: sorting vs counting complexity?

Sorting O(n log n). A 26-slot count array is O(n).

3 reasons strings are immutable (besides security)?

String pool sharing, thread safety, stable hash codes for HashMap keys.

Is Object.clone() deep or shallow?

Shallow. Inner objects are shared. You write deep copy yourself.
