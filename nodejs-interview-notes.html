1. What is Node.js? 0:51

Node.js is an open-source, cross-platform JavaScript runtime. A runtime is simply a program that can run your code. Before Node, JavaScript could only run inside a browser: you put it in a <script> tag in an HTML file and opened that file in Chrome. Node lets you run a .js file directly on your computer or a server, with no browser.

<!-- Before Node: JS only lived inside HTML in a browser -->
<script>
  console.log("Hello from the browser");
</script>

// With Node: save as app.js and run from the terminal
console.log("Hello from the server");
node app.js

Key traits: single-threaded, non-blocking (doesn't sit idle waiting), event-driven, fast (built on Google's V8 engine), and a huge library ecosystem (npm).

Correction: the video says cross-platform means "iOS, Android, Windows". In practice it means the same Node code runs on Windows, macOS and Linux servers.

3. Explain how Node.js works 4:19

Think of a restaurant with one very fast waiter (the event loop) and a kitchen with a few cooks (the thread pool). The waiter takes orders one by one. Quick things (pour water) the waiter does right away. Slow things (cook a meal) go to the kitchen, and the waiter keeps taking other orders. When a dish is ready, the waiter delivers it.

  1. Clients send requests.
  2. Requests are lined up in the event queue so none are lost.
  3. The event loop (the heart of Node, running on one thread) picks them up one by one.
  4. Non-blocking request → loop handles it quickly and sends the response.
  5. Blocking request (e.g. database query, heavy computation) → loop hands it to the libuv thread pool (a C library with a few background threads: T1, T2, T3…).
  6. When a thread finishes, it gives the result back to the event loop, which sends the response.
Correction: the video calls "reading a file" non-blocking and "DB query" blocking. More precisely: async file operations, DNS lookups, crypto and zlib use the libuv thread pool; network I/O (HTTP, most DB drivers) uses the OS's own async system and doesn't need the pool at all. The point that matters: slow work never blocks the main thread.

4. Why is Node.js single-threaded? 7:25

A thread is a worker that runs code. Traditional servers (e.g. old Java/PHP setups) create a new thread per request: 10,000 users = 10,000 threads, each using memory, and threads can fight over shared data (race conditions, deadlocks).

Node uses one main thread and never makes it wait. Slow work is handed off, so that one thread is free to serve thousands of requests.

  • Simpler — no thread conflicts or deadlocks to debug.
  • Lightweight & scalable — no per-request thread overhead.
  • Natural fit — JavaScript itself was always single-threaded.
Follow-up they may ask: "So is Node bad at anything?" Yes — CPU-heavy work (image processing, big loops) on the main thread freezes every user. Fix: worker_threads or move it to another service.

5. Why is Node.js so popular? 8:43

  • One language everywhere — JavaScript on both front end and back end.
  • Non-blocking, event-driven — handles many connections at once; great for real-time apps (chat, live updates).
  • npm — the biggest package library in the world.
  • Fast — V8 engine compiles JS to machine code.
  • Good for data streaming, APIs, microservices, proxy servers; high traffic with few resources.
  • Huge community; used by Netflix, LinkedIn, Uber, Walmart, eBay.

6. Hello World in Node.js 10:04

Steps: create a file → create a simple HTTP server → run it → open the browser.

// hello.js
const http = require('http');                 // built-in module, no install needed

const server = http.createServer((req, res) => {
  res.writeHead(200, { 'Content-Type': 'text/plain' });  // 200 = OK
  res.end('Hello World');                     // send body and finish
});

server.listen(8080, () => console.log('Running at http://localhost:8080'));
node hello.js

Open http://localhost:8080 → the page shows: Hello World

7. Synchronous vs asynchronous programming 12:02

Synchronous = one task at a time, in order. Each waits for the previous one to finish — like standing in a queue. If B takes 10 seconds, C waits 10 seconds doing nothing; the program is blocked.

Asynchronous = start a slow task, move on, and handle its result later when it's ready — like ordering food with a buzzer and sitting down instead of standing at the counter.

// Asynchronous — does not block
console.log('Start');
setTimeout(() => console.log('Fetching data...'), 1000);  // runs after 1s
console.log('End');

Start → End → (1 second later) Fetching data...

// Synchronous — blocks
const fs = require('fs');
console.log('Start');
const data = fs.readFileSync('example.txt', 'utf8');  // program stops here until read finishes
console.log(data);
console.log('End');

Start → (file content) → End — in strict order

8. How does Node.js achieve asynchronous programming? 15:02

Through its event-driven design and non-blocking I/O. When an async task starts (read a file, network call), Node hands it off and the main thread keeps going. When the task finishes, the event loop runs the function you attached to it.

Three tools to write async code (oldest → newest):

ToolSimple meaning
Callback"Call this function when you're done." A function passed as an argument.
PromiseAn IOU for a future value. Handle it with .then() (success) and .catch() (failure).
async/awaitWrite promise code that looks synchronous. await pauses only that function until the promise settles.

The video demo reads example.txt all three ways:

Callback

const fs = require('fs');

fs.readFile('example.txt', 'utf8', (err, data) => {   // error-first callback
  if (err) {
    console.error('Error reading the file:', err.message);  // e.g. file doesn't exist
    return;
  }
  console.log('File content:', data);
});

Promise

const fs = require('fs').promises;

fs.readFile('example.txt', 'utf8')
  .then(data => console.log('File content:', data))
  .catch(err => console.error('Error reading the file:', err.message));

async/await

const fs = require('fs').promises;

async function readMyFile() {
  try {
    const data = await fs.readFile('example.txt', 'utf8');  // waits here, thread stays free
    console.log('File content:', data);
  } catch (err) {
    console.error('Error reading the file:', err.message);
  }
}
readMyFile();

File exists → "File content: hello callback". File deleted → "Error reading the file: ENOENT..."

10. What is callback hell and how do you avoid it? 21:08

When each async step needs the previous step's result, you nest callbacks inside callbacks. The code drifts right into a triangle — the "Pyramid of Doom". It's hard to read, hard to change (every layer depends on the one above), and error handling is repeated at every level.

// Callback hell — notice the pyramid shape
getUser(1, (err, user) => {
  if (err) return console.error(err);
  getOrders(user.id, (err, orders) => {
    if (err) return console.error(err);
    getOrderDetails(orders[0], (err, details) => {
      if (err) return console.error(err);
      sendEmail(details, (err) => {
        if (err) return console.error(err);
        console.log('Done!');
      });
    });
  });
});

Fix 1 — Promises: flat chain, one .catch() for all errors.

getUser(1)
  .then(user => getOrders(user.id))
  .then(orders => getOrderDetails(orders[0]))
  .then(details => sendEmail(details))
  .then(() => console.log('Done!'))
  .catch(err => console.error(err));

Fix 2 — async/await: reads top to bottom like normal code.

async function run() {
  try {
    const user = await getUser(1);
    const orders = await getOrders(user.id);
    const details = await getOrderDetails(orders[0]);
    await sendEmail(details);
    console.log('Done!');
  } catch (err) {
    console.error(err);
  }
}

Fix 3 — control-flow libraries like async.js (async.waterfall, async.series). Less common now that async/await exists.

11. What are Promises in Node.js? 23:32

A Promise is an object that stands for a value you'll get later. Like a restaurant token: right now it's pending; later it's either your food (fulfilled/resolved) or "sorry, sold out" (rejected). Once settled, it never changes.

const myPromise = new Promise((resolve, reject) => {
  let success = true;               // set to false to simulate failure
  if (success) {
    resolve('Operation was successful');
  } else {
    reject('Something went wrong');
  }
});

myPromise
  .then(value => console.log(value))     // runs on resolve
  .catch(error => console.error(error)); // runs on reject

Operation was successful

Precisely, a promise has three states — pending, fulfilled, rejected — and the executor gets two functions, resolve and reject. The video blurs these; say both clearly.

12. How do you use async/await? 25:33

  • async before a function → it always returns a promise (even if you return a plain value).
  • await inside it → pause this function until the promise settles. Resolved → you get the value. Rejected → it throws, so wrap in try/catch.
  • Only that function pauses; the rest of the program keeps running.
function fetchData() {
  return new Promise(resolve =>
    setTimeout(() => resolve('Data received'), 1000));
}

async function main() {
  try {
    console.log('Fetching...');
    const result = await fetchData();   // waits 1s without blocking Node
    console.log(result);
    console.log('Function completed');
  } catch (err) {
    console.error('Promise rejected:', err);
  }
}

main();

Fetching... → (1s) Data received → Function completed

13. What is package.json? 26:44

The ID card + shopping list of a Node project. It records the project's details and which packages (dependencies) it needs, so anyone can run npm install and get the exact same setup.

npm init        # asks questions, then creates package.json
npm init -y     # same, accept all defaults
{
  "name": "my-app",
  "version": "1.0.0",
  "description": "My first Node app",
  "main": "index.js",                 // entry point: the file that starts the app
  "scripts": {
    "start": "node index.js"          // run with: npm start
  },
  "author": "Anshul",
  "license": "ISC",
  "dependencies": {                   // needed to run the app
    "express": "^4.19.2"
  },
  "devDependencies": {                // needed only while developing
    "nodemon": "^3.1.0"
  },
  "engines": { "node": ">=18" }       // required Node version
}
Real JSON doesn't allow comments — they're here only to explain. Also know package-lock.json: it locks the exact installed versions so every machine gets identical packages.

15. What is middleware and why is it used? 30:03

Middleware is a function that sits between the incoming request and the final response. Think of airport security checkpoints: each one checks something, then either lets you through (next()) or stops you (sends a response). Used for logging, authentication, parsing JSON, error handling.

const express = require('express');
const app = express();

// 1. Logger — runs for every request
app.use((req, res, next) => {
  console.log(`${req.method} ${req.url}`);
  next();                                   // pass to the next middleware
});

// 2. Auth — can stop the chain
function auth(req, res, next) {
  if (req.headers.token !== 'secret') {
    return res.status(401).send('Unauthorized');   // response sent → chain ends
  }
  next();
}

// 3. Built-in middleware to parse JSON bodies
app.use(express.json());

// Final handler
app.get('/profile', auth, (req, res) => res.send('Your profile'));

// Error-handling middleware has 4 args
app.use((err, req, res, next) => res.status(500).send('Something broke'));

app.listen(3000);

16. What is the purpose of module.exports? 31:53

module.exports decides what a file shares with other files. Whatever you put on it is exactly what require() returns. Benefits: modular code, reusability, abstraction (hide the details), separation of concerns.

// math.js
function add(a, b) { return a + b; }
function subtract(a, b) { return a - b; }
module.exports = { add, subtract };
// app.js
const { add, subtract } = require('./math');
console.log(add(2, 3));        // 5
console.log(subtract(5, 2));   // 3
Common follow-up: exports.add = add works too (it's a shortcut to module.exports), but exports = {…} does not — reassigning breaks the link. Modern alternative: ES modules, export / import.

17. Express.js vs Node.js 33:52

Node.js is the engine (runs JS on the server, gives raw tools like http). Express is a lightweight framework built on top of Node that makes driving that engine easier — routing, middleware, simpler request/response handling, less code.

Plain Node.js (http)Express.js
const http = require('http');

const server = http.createServer((req, res) => {
  if (req.url === '/' && req.method === 'GET') {
    res.setHeader('Content-Type', 'text/html');
    res.write('<html>');
    res.write('<head><title>Home</title></head>');
    res.write('<body>Hello</body>');
    res.write('</html>');
    res.end();
  } else {
    res.statusCode = 404;
    res.end('Not found');
  }
});
server.listen(3000);
 
const express = require('express');
const app = express();

app.get('/', (req, res) => {
  res.send('<html><body>Hello</body></html>');
});
// unknown routes → 404 automatically

app.listen(3000);
Analogy: Node = car engine. Express = steering wheel, gears and dashboard that make driving it smooth.

18. What is event-driven programming? 37:01

A style where code reacts to events (a click, a message arriving, data ready) instead of running top to bottom. Like a music app: nothing happens until you press Play — that press is an event, which triggers fetching the song and playing it.

Two core parts in Node: events (named signals like 'greet') and the EventEmitter (the manager that registers listeners and fires them).

const EventEmitter = require('events');
const emitter = new EventEmitter();

// Register a listener: "whenever 'greet' happens, run this"
emitter.on('greet', (name) => {
  console.log(`Hello, ${name}!`);
});

// Trigger the event, passing data
emitter.emit('greet', 'Alice');
emitter.emit('greet', 'Bob');

Hello, Alice!
Hello, Bob!

Note: emit() calls listeners synchronously, in the order they were added. The async part of Node comes from the I/O that causes events (e.g. a socket's 'data' event).

19. Role of the events module & how to handle events 40:01

The built-in events module gives you the EventEmitter class — the base of event-driven Node. Many core objects (HTTP server, streams, sockets) are EventEmitters underneath.

  1. Create an emitter: new EventEmitter()
  2. Listen: .on(event, fn) for every time, or .once(event, fn) for only the first time
  3. Emit: .emit(event, ...args)
  4. Stop listening: .off(event, fn) / .removeListener()
const EventEmitter = require('events');
const shop = new EventEmitter();

shop.on('order', item => console.log('Order received:', item));      // every time
shop.once('order', () => console.log('First order discount applied!')); // only once

shop.emit('order', 'Pizza');
shop.emit('order', 'Burger');

Order received: Pizza
First order discount applied!
Order received: Burger

20. Role of the Buffer class 41:16

JavaScript is built for text. But files, images, network packets are raw bytes (binary). A Buffer is a fixed-size chunk of memory holding raw bytes — each slot is one byte (0–255). Unlike an array it can't grow or shrink after creation.

const a = Buffer.alloc(5);          // 5 zero-filled bytes: <Buffer 00 00 00 00 00>
const b = Buffer.from('Hi!');       // from a string: <Buffer 48 69 21>
const c = Buffer.from([1, 2, 3]);   // from an array of bytes

a.write('Node');                    // write text into the buffer
console.log(a.toString());          // "Node" (+ one empty byte)
console.log(b.toString('base64'));  // "SGkh" — encoding support
console.log(b.length);              // 3

Used for: binary file handling, streams (data arrives as Buffer chunks), encodings (utf8, base64, hex).

21. setImmediate vs setTimeout 43:00

setImmediate(fn)setTimeout(fn, ms)
When it runsIn the check phase — right after the current poll (I/O) phaseIn the timers phase, once at least ms have passed
Use for"Run this as soon as the current I/O work is done""Run this after a delay"
const fs = require('fs');

// Inside an I/O callback the order is ALWAYS: immediate first
fs.readFile(__filename, () => {
  setTimeout(() => console.log('timeout'), 0);
  setImmediate(() => console.log('immediate'));
});

immediate
timeout

Correction: the video says setImmediate always has "higher priority". Not quite. In the main script (not inside I/O), setTimeout(fn, 0) vs setImmediate(fn) order is unpredictable — it depends on timing. Only inside an I/O callback is setImmediate guaranteed first (see the phase diagram in Q9: poll → check → … → timers). And process.nextTick() runs before both.

22. Explain Node.js web application architecture 44:14

Same as Q3, plus the outside world:

  • Client — browser/app sends requests.
  • Server — processes requests, bridges front end and database.
  • Event queue — holds requests in sequence.
  • Event loop — handles non-blocking requests, forwards blocking ones.
  • Thread pool — does blocking work separately so the loop stays free.
  • External resources — databases, file system, other services.

23. Types of streams 45:21

A stream processes data piece by piece (chunks) instead of loading it all into memory. Like drinking through a straw instead of swallowing the whole glass. Essential for big files and video.

TypeDoesExample
ReadableYou read from itfs.createReadStream(), req in a server
WritableYou write to itfs.createWriteStream(), res in a server
DuplexRead and write (two independent sides)net.Socket (TCP connection)
TransformDuplex that changes data as it passes throughzlib.createGzip() (compress)
const fs = require('fs');
const zlib = require('zlib');
const { pipeline } = require('stream');

pipeline(
  fs.createReadStream('input.txt'),      // Readable
  zlib.createGzip(),                     // Transform
  fs.createWriteStream('input.txt.gz'),  // Writable
  (err) => console.log(err ? 'Failed: ' + err.message : 'Compressed!')
);

24. Purpose of createServer() in the http module 46:34

http.createServer() creates a web server. You give it a function that runs on every request; it receives req (what the client asked for) and res (what you send back — HTML, JSON, images…). .listen(port) starts it.

const http = require('http');

const server = http.createServer((req, res) => {
  if (req.url === '/api/user') {
    res.writeHead(200, { 'Content-Type': 'application/json' });
    res.end(JSON.stringify({ name: 'Anshul' }));
  } else {
    res.writeHead(200, { 'Content-Type': 'text/plain' });
    res.end('Hello World');
  }
});

server.listen(8080, () => console.log('Listening on 8080'));

25. Most commonly used libraries 48:21

The video highlights two (and mentions body-parser and cors):

Express.js

Minimal, flexible web framework. Key features: routing, middleware, template engines, simple server setup. The go-to for APIs and web apps (see Q15, Q17).

Mongoose

An ODM (Object Data Modeling) library for MongoDB. It lets you define a schema (shape of your data), then gives you models to create/read/update/delete documents, with validation, middleware (hooks), querying and population (joining related documents).

const mongoose = require('mongoose');

await mongoose.connect('mongodb://localhost:27017/shop');

// Schema = the shape + rules for a document
const userSchema = new mongoose.Schema({
  name:  { type: String, required: true },   // validation
  email: { type: String, unique: true },
  age:   { type: Number, min: 0 }
});

// Model = the class you use to talk to the "users" collection
const User = mongoose.model('User', userSchema);

await User.create({ name: 'Anshul', email: 'a@x.com', age: 22 });
const adults = await User.find({ age: { $gte: 18 } });  // querying
Correction: the video calls Mongoose a "web application framework". It isn't — it's a database library (ODM) for MongoDB.

Others worth naming: cors (allow cross-origin requests), body-parser (now built into Express as express.json()), dotenv (env vars), jsonwebtoken (JWT auth), nodemon (auto-restart in dev), axios (HTTP client), socket.io (real-time).
